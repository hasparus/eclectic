# Paidotopos

Personal prototype playground in the eclectic Bun workspace. Next.js App Router, TypeScript, Tailwind v4, full shadcn/ui registry, next-themes, Playwright.

From repository root:

```sh
bun install
bun run --cwd packages/paidotopos dev
```

## Checks

```sh
bun run --cwd packages/paidotopos lint
bun run --cwd packages/paidotopos typecheck
bun run --cwd packages/paidotopos test
bun run --cwd packages/paidotopos build
```

## Thumbnails

From this directory, install Playwright Chromium once (`bunx playwright install chromium`). ffmpeg is needed only for MP4 social videos.

```sh
bun run thumbnails                          # all, builds and starts production
bun run thumbnails orbit-study             # one
bun run thumbnails orbit-study other-slug  # several (commas also supported)
bun run thumbnails --missing                # only absent previews
bun run thumbnails orbit-study --video      # light/dark PNG + interaction MP4
```

`--no-build` reuses a current production build. `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` selects a preinstalled Chromium. They run at 1200×800; no live apps run in gallery cards. PNGs are intentionally static. Missing images render a fallback. Inspect every capture before committing.

## Deployment

Import `hasparus/eclectic` into Vercel. Set Root Directory to `packages/paidotopos`, enable access to files outside the root, framework Next.js, install command `cd ../.. && bun install --frozen-lockfile`, build command `bun run build`. Connect the Git integration for an automatic preview deployment on every PR.

No authentication or deployment secrets are required. Optionally set `SITE_URL` to the canonical absolute origin; social metadata otherwise uses the request origin so branch previews share correctly. The repository includes PR lint, type-check, unit and production browser checks.

## Access and sharing

The owner explicitly removed the password gate. The gallery, all `/prototypes/<slug>` pages, thumbnails, and social files are accessible to anyone with the site URL, including in production. `hidden` only filters the gallery; neither `hidden` nor `public: false` protects content.

All metadata still starts with `public: false`: this flag opts into the share-friendly `/p/<slug>` alias and its social metadata, not access control. Those aliases and their preview endpoints return 404 for unflagged or unknown names. Flagged aliases include OG image, OG video, and Twitter metadata. Enable a share alias only when the owner asks; capture `--video` before setting `public: true`. Build validation requires an MP4 for every flagged prototype.

`lib/registry.generated.ts` is regenerated by builds and type checks. Discovery validates metadata and required files, then imports each page explicitly so direct and share URLs render the same component. Add a new folder, never maintain a manual registry.
